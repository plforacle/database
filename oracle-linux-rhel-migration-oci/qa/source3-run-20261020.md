## Read-only failure evidence and limits

Subsequent inspection found those seven files on a vfat filesystem. Every actual mtime was one second below the RPM mtime, while every size and SHA-256 matched the RPM metadata. Standard verification passed for all six deferred GRUB packages; shim returned `1` with timestamp-only differences. A diagnostic verification excluding mtime returned `0`. No file timestamp, payload, boot configuration, or package was repaired.

These observations support a filesystem timestamp-precision explanation for the final verification difference. They do not dismiss the earlier GRUB error or turn this run into a successful migration. A blanket mtime bypass is not established by this evidence.

The observed one-second truncation is consistent with the [Linux FAT implementation's two-second modification-time precision](https://github.com/torvalds/linux/blob/master/fs/fat/misc.c). RPM uses `T` for an mtime difference and separate flags for size, digest and other attributes; see the [RPM verification reference](https://rpm.org/docs/4.20.x/man/rpm.8). This supports a narrowly checked filesystem allowance, while leaving the independent GRUB error unresolved.
